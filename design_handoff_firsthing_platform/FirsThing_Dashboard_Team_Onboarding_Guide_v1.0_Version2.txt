# FirsThing.earth Next-Gen Platform – Product & Technical Blueprint
**Version:** 2.0 (Proposed)  
**Prepared for:** Rebuild + UI Redesign Program  
**Reference:** Existing FirsThing dashboard (legacy implementation)  
**Document Objective:** Define a complete, modern, scalable app that achieves the same business goals as the current dashboard, while improving functionality, architecture, usability, and operational reliability.

---

## 1) Executive Summary

The new platform will be a **role-based energy operations system** for societies, customers, admins, and inspection teams.  
It will unify:
- energy savings visibility,
- digital inspections,
- billing and invoice records,
- water tank monitoring,
- live metering analytics,
- and society onboarding lifecycle management.

The current app provides a strong functional base, but the new version should address:
- incomplete modules (inspection team, live metering, mobile parity),
- process fragmentation,
- manual-heavy reporting workflows,
- and limited automation/observability.

This blueprint defines a future-ready app with:
1. **complete end-to-end workflows**,
2. **clear role boundaries and permissions**,
3. **modular domain architecture**,
4. **mobile-first customer UX + productivity-focused admin UX**,
5. **data-driven reporting with auditability**,
6. **extensible integrations and AI-readiness**.

---

## 2) Product Vision & Goals

### Vision
Create a trusted digital operations platform that enables transparent, measurable, and actionable management of society-level sustainability and infrastructure performance.

### Primary Goals
1. Improve transparency in energy and utility outcomes.
2. Reduce manual operations effort for admin and field teams.
3. Enable faster decision-making with accurate, timely insights.
4. Maintain strong reliability and non-breaking continuity.
5. Scale to multi-society, multi-team operations.

### Success Metrics (KPIs)
- Monthly active societies / users by role
- Report publishing turnaround time
- Inspection completion cycle time
- Invoice reconciliation time
- Customer engagement (view/download rates)
- Data latency for live metering
- Ticketed support issues per release
- Uptime and failed workflow rate

## 3) User Personas & Role Model

## Core Roles
1. **Platform Admin**
   - Global management of societies, users, reports, invoices, devices, policies.
2. **Society Admin / Manager (optional expanded role)**
   - Society-specific operations, member/user governance, local review approvals.
3. **Customer**
   - Views dashboards, reports, invoices, metering insights, water tank status.
4. **Inspection Team**
   - Conducts on-ground inspections, uploads evidence, submits digital reports.
5. **Finance/Operations Analyst (future)**
   - Cross-society trend analysis, export and compliance packages.
6. **Support/Read-only Auditor (future)**
   - Access to immutable logs and reports without edit permissions.

## Permission Model
Use **RBAC + scoped resource permissions**:
- Role-level access (Admin/Customer/Inspector)
- Society scope restrictions (single vs multi-society visibility)
- Action-level rights (view/create/edit/approve/publish/delete)
- Field-level restrictions for sensitive data (invoices, contact info)

## 4) Functional Scope (Complete System)

## 4.1 Authentication & Identity
- Email/password + OTP/magic link options
- Optional SSO (future enterprise support)
- Profile lifecycle: invited → activated → role assigned → society mapped
- Session management, password reset, device session view
- Security logs for sign-ins and profile changes

### Requirements
- Mandatory role assignment before dashboard access
- Forced completion of profile basics on first login
- Secure invite flow with expiry and resend controls

---

## 4.2 Society Lifecycle Management
- Create society with metadata (name, address, contacts, service type)
- Associate users, assets, meters, and reports
- Status workflow (onboarding, active, suspended, archived)
- Society-level settings (timezone, reporting frequency, SLA profile)

### Requirements
- Guided onboarding wizard with validation checklist
- Bulk upload support for initial data seeding
- Timeline history of all onboarding actions

---

## 4.3 Customer Dashboard
- Personalized savings overview (monthly/quarterly/yearly)
- Latest reports and invoices quick access

### UX Requirements
- Mobile-first responsive design
- 3-click access to critical artifacts (reports/invoices)

## 4.4 Admin Dashboard
- Portfolio-wide KPIs across societies
- Pending tasks queue (uploads, approvals, anomalies, expiring contracts)

### UX Requirements
- Desktop-optimized analytical layout

## 4.5 Reports Management
### Types

- Compliance/Custom Reports (future)

### Features
- Upload, versioning, publish/unpublish
- Metadata tagging (society, period, type, status)

## 4.6 Digital Inspection Module
- Task assignment to inspectors
- Mobile inspection forms/checklists
- Photo/video evidence uploads
- On-site readings capture with timestamp + geo-tag (optional)
- Supervisor review and closure

### Workflow
Planned → Assigned → In Progress → Submitted → Reviewed → Closed

### Requirements
- Offline-capable field entry with sync retry
- Mandatory evidence for critical checklist items
- Auto-generated inspection report from structured data

---

## 4.7 Invoice & Billing Module
- Invoice upload and metadata extraction
- Status states (issued, due, paid, overdue, disputed)

### Requirements
- Due-date reminders

## 4.8 Live Metering & Analytics

- Data ingestion pipeline (stream/batch)

### Requirements
- Data quality checks (missing intervals, outliers, stale feeds)
- Last-updated indicators on all metering widgets
- Methodology transparency panel (how numbers are derived)

---

## 4.9 Water Tank Monitoring
- Tank level telemetry (manual + IoT feed support)
- Threshold alerts (low/high/abnormal)
- Event history and maintenance log
- Society-wise summary views

### Requirements
- Alert subscriptions by role
- Escalation rules for prolonged critical status

## 4.10 Notifications & Communication

## 6) Non-Functional Requirements

## Performance
- <2.5s initial dashboard render target (p50 broadband)
- API p95 response under 500ms for common queries
- Incremental loading for large tables/charts

## Reliability
- 99.9% monthly uptime target
- Graceful degradation when external feeds fail
- Idempotent ingestion and background jobs

## Security
- Row-level security and policy testing
- Encrypted data at rest and in transit
- Signed URL strategy for document access
- PII minimization + masking where possible

## Scalability
- Multi-tenant readiness by society
- Queue-backed async processing for heavy tasks
- Caching strategy for dashboard aggregates

## Maintainability
- Domain-oriented modular code boundaries
- Clear separation: UI / application logic / data layer
- Strong typing and API contracts
- Comprehensive observability and error monitoring

## 7) Recommended Technical Architecture (Optimized)

Current baseline (Next.js + TypeScript + Supabase) is valid and can be retained, but structured better.

## 7.1 Frontend
- Next.js App Router
- TypeScript strict mode
- Tailwind + component system (design tokens)
- React Query / TanStack Query for server-state handling
- Form layer with Zod validation + reusable schemas

## 7.2 Backend & Data
- Supabase Postgres with robust schema normalization
- Supabase Auth + explicit profile/role mapping
- Edge Functions for domain workflows/integrations
- Background jobs for report generation, notifications, ingestion cleanup

## 7.3 Data & Analytics
- Time-series table strategy for metering/tank feeds
- Precomputed aggregates/materialized views for dashboards
- Data quality flags and confidence scoring in analytics pipeline

## 7.4 Infrastructure
- Keep Lightsail initially or migrate toward containerized deployment path
- Nginx as reverse proxy + caching headers
- PM2 acceptable short term; long term prefer orchestrated runtime
- CI/CD with staged environments (dev/staging/prod) and migration gates

## 7.5 Observability
- Centralized logs, error tracking, uptime checks
- Product analytics for feature usage
- Audit dashboards for admin actions and ingestion health

## 8) UI/UX Redesign Requirements

## Design Principles
1. Clarity over density
2. Explainability for all computed metrics
3. Action-first workflows for admin
4. Mobile-first simplicity for customers
5. Consistent component patterns and states

## Design System Foundations
- Color tokens: semantic (success/warn/error/info)
- Typography scale and spacing grid
- Standard table/chart/card primitives
- Empty/loading/error/skeleton states
- Accessibility compliance baseline (keyboard + contrast)

## Role-Specific UX
- **Customer:** card-centric, minimal complexity, guided insights
- **Admin:** data-dense, filter-heavy, workflow accelerators
- **Inspector:** task-driven mobile flow, offline-friendly, media capture priority

## 10) Migration Strategy from Current App

1. **Discovery:** Map legacy modules and data entities.
2. **Schema Alignment:** Design new schema with migration adapters.
3. **Parallel Run:** Keep old app operational while new modules go live incrementally.
4. **Cutover by Domain:** Migrate module-by-module (reports → invoices → inspections → metering).
5. **Validation:** Reconcile metrics and report parity before retiring old flows.

---

## 11) Risks & Mitigations

- **Risk:** Incomplete data quality for metering feeds  
  **Mitigation:** ingestion validation, fallback states, data freshness indicators

- **Risk:** Role/permission leakage  
  **Mitigation:** policy test suite + explicit authorization middleware checks

- **Risk:** Scope creep during redesign  
  **Mitigation:** strict phase gates and MVP definitions

- **Risk:** Operational disruption during migration  
  **Mitigation:** dual-run strategy and society-level rollout toggles

---

## 12) Definition of Done (Program-Level)

A release is complete when:
- All role-based primary journeys are executable end-to-end
- Published reports/invoices are versioned, auditable, and downloadable
- Inspection workflow fully digital with evidence and approvals
- Live metering and water tank modules display reliable freshness/status
- KPI dashboards and operational alerts function across target societies
- Security, performance, and observability baselines pass acceptance criteria
